# /uify

Mind: {{mind}}
Argument: [target or direction]

## Start

The unit only decides where the report goes. With no active role, or with no mind installed, this paragraph is skipped: the pass runs on the subject and reports in the reply. Otherwise, locate the mind through the Mind line above. Read `machines/<host>.md` in its `user/` folder, where `<host>` is the hostname of this machine, and take the paths from its `Paths` section. Resolve the current project from the working directory against those paths, and the unit as the role of the current chat plus that project; executive roles use the role name alone. When the machine file is missing, the pass runs anyway and reports in the reply. The layout of the mind and the format of every file are in `files.md`, next to `rules.md`: the steps name the files and do not repeat the formats.

## Steps

1. Read the argument. With none, the subject is the whole rendered surface in front of the session, the open page or app and every view reachable from it, and the pass is a refine inside its current identity: floors, states, tokens, structural words and layout defects are fixed; the look, the page structure and the behaviour behind the interface stay. The defaults that belong to the look are sorted by [defaults.md](../defaults.md), In a refine: the floors they break are fixed, the treatment is reported. The behaviour behind the interface is requests, endpoints, payloads, stored data and server logic. Focus handling, a native dialog in place of a division, a confirmation before a destructive action, inline messages, a disabled state with its reason, a guard against a double submit and other client-side state are interface, and are in the pass. An argument that names something, such as `form`, `the pricing card` or `the header`, is a target and narrows the pass to it. An argument that describes a change, such as `switch to a medieval theme`, `add icons` or `add storytelling`, is a direction and steers the pass across the subject. A request that names a whole surface and then points at one defect is a target on that defect. Say the reading in one line; when two readings lead to different work, ask before going further.

2. Resolve the categories. For a whole surface or a build, read [essentials.md](../essentials.md) first. Match the subject against the category lines and the routing table in [INDEX.md](../INDEX.md), which name the protocols and topics without opening the category files. Open a category file only to choose an option, for a target, a direction or a build, or to read its `Build:` recipe. A target usually touches one to three subcategories. A direction adds its own subcategory: a look goes to direction and restyle in foundations, `add icons` to icons in media and icons, `add storytelling` to storytelling in pages and composition and to scroll and storytelling in motion. Name the subcategories in one line, with the option taken only where the pass changes something.

3. Collect the passes. Take the protocol steps and topic sections the routing names, deduplicated, and read only those: a topic by the sections named after it, and a protocol only when [steps.md](../steps.md) shows that at least one of its steps will actually run on this surface. A refine of a whole surface starts from the floor set at the end of that file. [visual-critique](../protocols/visual-critique.md) and [accessibility](../protocols/accessibility.md) are always in the set. The passes scale to the surface, as in [evidence.md](../evidence.md), Proportion: a step with nothing to act on ends as not applicable. Name the protocols in one line.

4. Plan before editing. Write the subject, its audience and its primary job in one line each, the mode of the surface, and the design plan: the palette as four to six named values with a role each, the type roles and faces, the layout in one sentence, the motion level, and the one place where boldness is spent. For a direction, add the direction contract from [direction.md](../direction.md). Check the plan against [defaults.md](../defaults.md) and rewrite whatever reads as a default; in a refine, sort each default as that file's In a refine section says instead. No file is edited before the plan exists. A refine with no argument and a named target proceed after the plan. A yes from the requester comes first for a direction, a restructure of the page, a change of behaviour behind the interface, a removed section, and anything [direction.md](../direction.md) says never moves silently. With nobody to ask, each of those is reported as open with its fix.

5. Apply within the boundary. A target changes only the target; a neighbour that now looks inconsistent is reported, not fixed. A refine changes the whole surface inside its identity. A direction moves the primitive layer, the faces and the assets, and components only where the direction itself is the component change, such as adding icons. A direction that would force a component to change for a look alone is recorded as a gap in the token layer. Structural words are part of this pass and are written in the interface's existing language, then flagged for the copy pass: visible field labels, accessible names, the inline reason of a disabled control, the action of an empty state, the recovery of an error, the skip link. Persuasive and explanatory text is handed to copy. Serving the surface for the pass never edits a tracked file: the project's own start command first. When that command fixes its port in a tracked file, the port is overridden at runtime, for example through an environment value or a wrapper that sets the listen port, rather than by editing the file. A static server on a free port is the last resort, because it loses the states driven by the API, and those states are then recorded as not verifiable.

6. Verify in the browser. Run each collected step against the rendered surface and produce the artifacts it asks for: computed numbers, captures of each state in each theme that ships where colour moved, searches with zero hits, the keyboard walk transcript, the written critique. A check the tool cannot perform is recorded as in [evidence.md](../evidence.md), Tool limits, with what a person must check, and the pass continues; any other check that could not be run is reported as not run.

7. Hold the floors. The pass stops, is fixed and is measured again if any contrast pair falls below its target in [essentials.md](../essentials.md#floors), or if the keyboard walk breaks at any stop. Nothing continues past either failure, whatever the direction asks.

8. Report the evidence. Give the reading, the subcategories and options taken, the protocols run, the numbers, the named captures, the findings ranked by the scale in [evidence.md](../evidence.md) with a fix against each, the structural words added for the copy pass, the fresh-eyes verdict, the open items that waited for a yes, and whatever could not be verified. The evidence goes in the task report when a task is open, otherwise in the reply.
