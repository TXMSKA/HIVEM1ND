# Protocol steps

What each protocol step checks, in a few words, so a pass can pick its steps from the [routing table](INDEX.md#routing) without opening every protocol. A protocol file is opened only when at least one of its steps will actually run; a step whose subject the map does not contain ends as not applicable from its line here. Each protocol file holds the task, the time and the result that counts as evidence.

- [version-floor](protocols/version-floor.md): 1 runtime major against its support calendar; 2 installed versions from the lockfile, unused declared packages included; 3 each framework against its vendor advisories fetched in the pass; 4 the advisory database as a second pass; 5 the deployed build carries the same versions; 6 the floor enforced in the pipeline.
- [supply-chain](protocols/supply-chain.md): 1 install scripts in the manifest and their default refusal; 2 minimum release age; 3 clean install from the lockfile in the pipeline; 4 pinned workflow actions and a read-only default token; 5 the dependency audit and what it does not prove; 6 what a new dependency ships.
- [secrets](protocols/secrets.md): 1 working tree scan; 2 history scan with live credentials told apart; 3 secret values in the build output; 4 tracked environment files; 5 rotation before history rewrite; 6 one least-privilege key per consumer; 7 scans in the hook and the pipeline.
- [deployment-surface](protocols/deployment-surface.md): 1 environment and git files requested over HTTP (a static file handler also takes injection-and-output 3); 2 default credentials; 3 stock, debug and health routes and leftovers; 4 directory listing on static paths; 5 source maps on the public origin; 6 pipeline secrets scoped to their jobs; 7 the hosting shape recorded.
- [access-control](protocols/access-control.md): 1 inventory of every route, action and job that takes an identifier; 2 another account's objects at the same role; 3 privileged endpoints as an ordinary and an anonymous caller; 4 fields a role may not write or should not read; 5 the check inside the action, called without the page; 6 identity read only from the session; 7 unmatched paths and new endpoints denied by default.
- [authentication-and-session](protocols/authentication-and-session.md): 1 session cookie attributes as served; 2 logout route and timeouts in the source, then rotation at login, revocation at logout and expiry at runtime; 3 tokens in URLs, logs and browser storage; 4 password hashing and login throttling; 5 reset, invitation and setup links single use and expiring; 6 account enumeration by status, body and timing; 7 token lifetimes, signed-token algorithm and the second factor.
- [payments-and-webhooks](protocols/payments-and-webhooks.md): 1 money fields the client sends; 2 server recompute proved by tampering; 3 webhook signature and timestamp checked before the body; 4 idempotent handler under replay and reorder; 5 fulfilment driven by the provider, not the client; 6 card data off the servers and reconciliation.
- [outbound-requests](protocols/outbound-requests.md): 1 every fetch of a URL taken from input; 2 loopback and metadata addresses through each one; 3 redirects and name resolution to internal addresses; 4 third-party responses validated and bounded; 5 signatures on emitted webhooks.
- [file-upload](protocols/file-upload.md): 1 accepted types checked by content; 2 generated storage names against hostile filenames; 3 stored files served as data from outside the web root; 4 decoder libraries against their advisories; 5 size, count and archive expansion ceilings; 6 authentication, ownership and rate limit on upload and download.
- [cross-site-requests](protocols/cross-site-requests.md): 1 forgery token on every state change; 2 no state change on GET or HEAD; 3 SameSite recorded as depth, not the control; 4 cross-origin headers for allowed, unlisted, null and lookalike origins; 5 framing refused.
- [headers-and-transport](protocols/headers-and-transport.md): 1 headers on a success and on an error; 2 comparison with the published set, or the baseline when not fetched; 3 headers that name the stack; 4 dead headers present; 5 enforcing content security policy; 6 HTTPS redirect, protocol versions and strict transport; 7 certificate chain, expiry and revocation.
- [injection-and-output](protocols/injection-and-output.md): 1 schema validation and limits on every input; 2 query concatenation and allowlisted identifiers; 3 shell execution, evaluation and paths built from input, the static file handler included; 4 raw HTML sinks; 5 an injected inline script blocked by the policy; 6 open redirects and unsafe deserialisers; 7 the payload set at every parameter.
- [data-store](protocols/data-store.md): 1 every store and the account each environment uses; 2 grants per runtime account; 3 row policies where the browser reaches the data; 4 migrations on their own account and trigger; 5 encryption in transit and sensitive fields at rest; 6 a restored backup and test runs kept off real data.
- [resource-limits](protocols/resource-limits.md): 1 a limit on every entry point and its key; 2 each ceiling reached once; 3 page size, offset, sort and search bounds; 4 body, header, timeout and connection limits; 5 spend caps that halt; 6 limits on whole business flows.
- [model-exposure](protocols/model-exposure.md): 1 provider key and calls kept on the server; 2 tools the model can call and what they change; 3 a person before high-impact actions; 4 injection through every channel, graded at the boundary; 5 no control resting on the system prompt; 6 input, output and spend caps on every model endpoint; 7 generated output treated as untrusted at each sink.
- [logging-and-errors](protocols/logging-and-errors.md): 1 swallowed exceptions and fall-through to success; 2 each failure class closes by default at runtime; 3 internals in error responses; 4 the security events actually logged; 5 secrets and personal data in the records; 6 an alert raised by a bounded attack; 7 retention, append-only sink and clocks.

A whole pass on a small surface takes the category rows the map touches, reads the lines above, and opens only the protocols with a step that applies: an application with no payments, uploads, outbound fetches or model calls never opens those four files.
